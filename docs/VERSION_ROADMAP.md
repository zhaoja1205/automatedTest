## V1.0.0 — 规则引擎版 ✅ 已完成

### 定位

纯代码逻辑 + 正则规则驱动，无 AI 依赖。稳定可靠的基线版本。

### 核心能力

| 模块 | 能力 | 实现方式 |
|---|---|---|
| 命令解析 | 从自然语言步骤提取可执行命令 | 26 条正则 + 关键字白名单 |
| 执行引擎 | 顺序执行 + nvsipl 并行模式 | SSH/PTY channel |
| 结果判定 | 关键字匹配 + FPS 检测 + 错误扫描 | 规则引擎（阈值固定） |
| NA 识别 | 自动识别不适用用例 | 关键字匹配 |
| 报告输出 | Excel 回写状态和结果 | openpyxl 原地修改 |

### 技术栈

- 后端：Python / FastAPI / Paramiko / openpyxl
- 前端：React / TypeScript / Ant Design / Zustand
- 通信：WebSocket 实时推送
- 无外部 AI 服务依赖

## V2.0.0 — AI 辅助判定版 ✅ 已完成

### 定位

在 V1 规则引擎基础上，**结果判定和失败分析**引入 AI 能力。命令解析保持规则方式不变。

### 已实现能力

| 能力 | 说明 | 触发方式 | 状态 |
|---|---|---|---|
| **AI 结果判定** | LLM 对比预期结果与实际输出，语义级 Pass/Fail 判定 | 三种模式可选（始终/不确定时/关闭） | ✅ |
| **AI 失败分析** | 失败用例自动分析根因、证据和修复建议 | 用户点击 / 可配自动 | ✅ |
| **AI 报告生成** | 执行完成后生成结构化测试报告 | 用户触发 | ✅ |
| **AI 配置面板** | 独立配置页面：Provider/Key/模型/URL/功能开关 | 侧边导航 | ✅ |
| **中智网关适配** | ThunderSoft LLM 网关兼容（Claude 协议代理） | 预填 URL + 自动路由模型 | ✅ |

### 架构

```
V2.0.0 流程:
  步骤解析(规则) → 执行 → 结果判定(规则+AI) → AI失败分析 → AI报告 → 输出
                                │                      │            │
                                ▼                      ▼            ▼
                         ┌─────────────┐      ┌─────────────┐ ┌────────┐
                         │ 规则判定     │      │ 根因分析     │ │ 报告   │
                         │   ↓ 不确定   │      │ 证据提取     │ │ 趋势   │
                         │ AI语义判定   │      │ 修复建议     │ │ 建议   │
                         └─────────────┘      └─────────────┘ └────────┘
```

### AI 判定模式

| 模式 | 配置值 | 说明 |
|---|---|---|
| 始终 AI 判定 | `always` | 每条用例执行后 AI 根据 log 分析 Pass/Fail（默认） |
| 仅不确定时 | `uncertain` | 规则引擎置信度低时才调用 AI |
| 关闭 | `off` | 仅用规则引擎判定 |

### AI 配置

```python
    ai_auto_parse_steps: bool = True     # Phase 3 新增
    ai_judge_mode: str = "always"        # off / uncertain / always
    ai_cache_ttl_hours: int = 24
```

## V3.0.0 — 全智能版 🔧 开发中

### 定位

测试步骤解析也引入 AI，实现从用例加载到报告输出的**全链路 AI 赋能**。

### 已实现能力

| 能力 | 说明 | 状态 |
|---|---|---|
| **AI 步骤解析** | LLM 理解自然语言步骤，提取命令、交互模式、操作类型 | ✅ 已完成 |
| **多会话隔离** | 多 PC 并行测试，session 级状态/SSH/文件/WebSocket 完全隔离 | ✅ 已完成 |
| **故障测试交错执行** | PTY 命令与 shell 命令按步骤原始顺序交替执行 | ✅ 已完成 |
| **跳板机 SSH 增强** | sshpass + ProxyCommand 双密码回退，解决 Paramiko cipher 不兼容 | ✅ 已完成 |
| AI 用例推荐 | 基于变更/历史推荐执行范围 | 📋 规划中 |
| AI 自适应执行 | 动态调整超时、重试策略、执行顺序 | 📋 规划中 |
| AI 用例生成 | 从需求文档自动生成测试用例草稿 | 📋 规划中 |
| 多项目适配 | 工具描述文件 + AI 自动适配新项目 | 📋 规划中 |

### AI 步骤解析 ✅

**V1/V2 方式**：正则规则（需统一用例格式）
**V3 方式**：LLM 理解任意格式的步骤描述

```
输入 (自然语言):
  "先把camera跑起来用30fps的配置，等出帧后查一下al看像素对不对"

AI 输出 (结构化):
  [
    {"command": "./nvsipl_camera -c ...", "kind": "command", "confidence": 0.85},
    {"command": "gc 10", "kind": "nvsipl_input", "confidence": 0.92},
    {"command": "al", "kind": "nvsipl_input", "confidence": 0.95}
  ]
```

**实现特性**：
- 上传 Excel 后自动触发异步批量解析（`asyncio.create_task` 不阻塞响应）
- 识别 5 种操作类型：`command` / `cd` / `nvsipl_input` / `manual` / `skip`
- 解析结果缓存，相同步骤文本不重复调用 AI
- WebSocket 实时推送解析进度
- 前端 🤖 标记标识已解析用例
- 可通过 AI 配置面板开关控制（`ai_auto_parse_steps`）
- 执行启动时自动中断未完成的批量解析，让出 API 资源

### 架构演进

```
V3.0.0 全链路:

  用例加载 → AI步骤解析 → 执行 → AI结果判定 → AI失败分析 → AI报告
     │            │                      │            │          │
     ▼            ▼                      ▼            ▼          ▼
  多格式      语义理解               语义匹配      根因定位    趋势+建议

  session     交互识别                            修复建议
  隔离        操作分类
```

### 风险控制

| 风险 | 对策 |
|---|---|
| AI 解析出错误命令 | 解析结果前端可视化 + 🤖 标记 + 置信度展示 |
| 幻觉命令 | 解析结果仅供参考，不直接替换规则引擎执行 |
| API 延迟 | 异步解析不阻塞上传，解析与执行互不干扰 |
| 成本 | 缓存机制（相同步骤不重复调用） + 可配关闭开关 |
| 执行冲突 | 执行启动时自动中断批量解析 |
