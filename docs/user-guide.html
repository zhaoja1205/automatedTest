快速上手

完整执行一次测试的基本流程：

配置 SSH → 配置工作区 → 上传 Excel → 勾选用例 → 开始执行 → 下载结果

SSH 连接配置

点击工具栏「SSH 配置」按钮，配置板端连接信息。支持直连和跳板机两种模式。

A直连模式（Direct）

PC 直接 SSH 连接目标板端。

字段说明
host板端 IP（如 10.127.1.100）
portSSH 端口，默认 22
username登录用户名（如 root）
password登录密码
target_password板端 sudo 密码（用于 sudo 操作时自动注入）
timeout连接超时秒数（默认 30，范围 1-300）
B跳板机模式（Jump）

先登录跳板机，再通过跳板机隧道连接目标板端。适用于板端不在本机网段的场景。

字段说明
jump_host跳板机 IP
jump_port跳板机 SSH 端口
jump_username跳板机用户名
jump_password跳板机密码
跳板机模式使用 Paramiko 双跳建立连接。若目标板端仅支持 AES-GCM 等 Paramiko 不兼容的加密套件，直连模式会自动回退到系统 OpenSSH，但跳板机模式不支持回退。

配置完成后点击「测试连接」，连接成功后状态栏显示绿色。

工作区配置

点击工具栏「工作区配置」按钮，设置执行参数和路径覆盖规则。

◇基础配置
字段说明
tester_name测试人姓名，自动写入 Excel 结果的「测试人」列
test_version测试版本号，写入「测试版本」列
default_remote_path板端测试命令的工作目录（如 /storage/zja/），所有命令在此目录下执行
run_prerequisites是否在每个用例执行前先运行「前提条件」列中的命令
▤路径覆盖配置

当用例中的路径需要统一替换时，启用对应覆盖选项：

选项作用
nito_override启用后替换命令中 --nito /path 的路径为配置值。用于统一指定 nito 库位置。
image_storage启用后替换命令中 -f /path/ 参数为配置的存储目录。用于统一拍照文件存储位置。
cam_rotate_cfg启用后覆盖用例中 export CAM_ROTATE_CFG_PATH=... 的值。用于指定板端翻转配置文件的实际路径。
Camera 翻转配置文件需人工推送到板端（使用「推送文件」功能），此处仅配置环境变量覆盖路径。
⬇拍图下载配置
选项作用
image_download启用后，拍照用例执行完成后自动将板端生成的图片 SCP 下载到 PC 本地（按 case_id 分目录），下载完成后清理板端文件。

上传用例

点击「上传测试用例」选择 .xlsx 文件。系统解析所有 Sheet 页中的用例，每个 Sheet 作为独立分组。

Excel 格式要求：

  • 第一行为表头（自动匹配列名）
  • 必须包含：用例编号、测试步骤、预期结果
  • 可选列：用例描述、前提条件、优先级、测试类型等

上传后 Sheet 切换栏出现，可按页签查看和选择用例。

执行测试

勾选需要执行的用例（支持全选当前页），然后点击「开始执行」。

执行过程

  • 顶部进度条实时显示当前进度和正在执行的用例 ID
  • 底部日志面板实时推送命令输出、匹配判定、错误信息
  • 用例表格中状态列实时更新（Running → Pass/Fail/Review）
  • 可随时点击「停止执行」终止（当前命令会被强制中断）

人工确认

当用例步骤包含人工确认环节（或预期结果需要人工核对 metadata），界面会弹出确认卡片，显示步骤描述和「确认 Pass」/「确认 Fail」按钮。超时未响应将自动跳过。

执行完成

全部用例执行完后，点击「下载结果」导出带有实际结果、判定状态的 Excel 文件。

文件推送

点击「推送文件到板端」按钮，支持两种模式：

↑推送功能
模式说明
PC 本地路径填写 PC 上的绝对路径（文件或目录），通过 SCP 推送到板端指定路径。目录会递归推送。
浏览器选择文件通过浏览器文件选择器选取单个文件上传到板端。

可选「推送后复制到运行 so 路径」，勾选后输入目标 SO 路径，系统会在推送完成后执行板端 cp 命令将文件复制到指定位置（Linux 用 sudo cp，QNX 用 cp）。

用例编写规范

在 Excel 的「测试步骤」列编写操作序列，系统自动解析每一行为独立步骤。支持以下格式：

命令类步骤

$直接命令

以下写法均可被识别为可执行命令：

1、输入命令：./nvsipl_camera -c /path/config.json -m "0x0001" -r 5 2、执行命令：i2ctransfer -f -y 30 w2@0x36 0x30 0x1a 3、./nvsipl_camera -c cfg -s --writeFrames 1 -Z 4、sudo chmod 777 /dev/i2c-30

关键字触发：输入命令:、执行命令:、测试指令:、起流:，或直接以 ./、sudo、nvsipl_camera 开头。

⇄环境变量 / Shell 内置
2、输入export CAM_ROTATE_CFG_PATH=/storage/test/config.json 3、source /opt/env.sh

export 和 source 命令被识别为 shell 内置命令，不会与 nvsipl 交互输入混淆。在「持久 Shell 模式」下环境变量在整个会话内有效。

⟳nvsipl 交互子命令
2、输入 gc 3、输入 dl 8 4、执行 el 11, al

在阻塞型 nvsipl_camera 运行时注入的交互命令。支持：gc、dl、el、al、ro、q、sr、hs 等。多个子命令用逗号或分号分隔。

控制类步骤

↺重复步骤
// 重复指定范围 4、重复步骤1-3 // 重复单步 3、重复步骤1 // 反复起流（压力测试） 3、反复起流10次

「重复步骤N」会重新执行第 N 步的命令。「反复起流 N 次」会循环 N 次完整的 nvsipl 启动→gc→检测fps→q退出 流程。

⚠人工操作 / 确认
// 自动跳过的人工操作 2、手动切换 Camera 通道 // 需要人工确认的步骤（前缀 MANUAL_CONFIRM） MANUAL_CONFIRM 检查屏幕是否有显示异常

含「手动/人为/拔插/物理操作」等关键字的步骤自动跳过（标记为人工操作）。MANUAL_CONFIRM 前缀的步骤会在前端弹出确认对话框等待点击。

特殊场景：拍照 + 环境变量 + 重复

◆持久化 Shell 模式（自动触发）

当用例同时包含 nvsipl 命令 + export + 重复步骤 三要素时，系统自动启用持久化 Shell 模式（invoke_shell），确保环境变量在同一终端会话内生效。

1、输入命令：./nvsipl_camera -c cfg -f /storage/zja/ -s --writeFrames 1 -Z 2、输入export CAM_ROTATE_CFG_PATH=/storage/test/config.json 3、重复步骤1

执行流程：

  1. 打开持久 PTY Shell → cd 到工作目录
  2. 第一次拍照：命令中 -f /storage/zja/ 自动补充为 -f /storage/zja/default
  3. 发送 gc 触发出帧 → 等待 writeFrames 完成自动退出
  4. 执行 export（若工作区配置了 cam_rotate_cfg 覆盖，使用配置值）
  5. 第二次拍照：-f /storage/zja/rotate（自动区分文件名）
  6. 关闭 PTY，合并两次输出进行判定
文件命名规则：当 -f 路径以 / 结尾（无前缀），第一次自动补充 default，第二次补充 rotate。已有前缀的路径（如 -f /path/myname）不修改。

预期结果编写

在「预期结果」列用自然语言描述期望的输出，系统自动提取匹配规则。

✓帧率检测
// 精确帧率（±20% 容差） 预期结果：30fps 正常出帧 // 帧率稳定性（仅检查 > 20fps） 预期结果：正常起流，帧率稳定 // 帧率范围 预期结果：帧率在 25-30fps 之间

系统自动从输出中匹配 Frame rate (fps): 29.99 格式的帧率数据，按 sensor 分别验证。

📄文件生成检测
// 检查是否有 .yuv 文件生成 预期结果：生成 .yuv 文件 // 检查文件数量 预期结果：生成两个 .yuv 文件 // 也支持阿拉伯数字 预期结果：生成 3 张 .raw 文件

支持后缀：.raw、.yuv、.png、.jpg、.log、.txt、.csv。

数量验证（支持中文「两/三/四...十」和数字）：找到的文件数 ≥ 预期数即 Pass。

文件搜索目录：优先使用「image_storage_path」配置（如已启用），否则使用 default_remote_path。在板端搜索最近 3 分钟内生成的文件。
🔑关键字匹配
// 引号内的文本会被精确匹配 预期结果：日志中包含"streaming"和"initialized" // 无报错检测 预期结果：无报错，正常退出 // 十六进制值匹配 预期结果：寄存器值为 0x1A3F

匹配规则：所有提取的关键字在实际输出中匹配率 ≥ 80% 即 Pass。支持英文关键字自动提取、引号关键字精确提取、十六进制值匹配。

⏱帧同步检测
// 自动触发条件：命令含 --showmetadata 预期结果：帧同步误差小于5ms

当命令含 --showmetadata 参数时自动进入帧同步检测模式，解析各 Camera 的 TSC SOF 时间戳，按时间片分组计算最大差值，与阈值比较。

📊其他支持的模式
  • DL/EL 阶段检测：当输出含 Disable Link / Enable Link 时，自动按阶段分析各传感器状态变化
  • 嵌入行信息（metadata）：预期含曝光/增益/帧序号 + 输出含 Camera ID/Frame Counter，自动截取 metadata 并标记"待确认"
  • SR/HS 用例：预期含 ROI/直方图 + 输出含相关特征，标记"待确认"供人工核对

状态与判定

状态含义触发条件
Pass通过关键字匹配率 ≥ 80% 且无严重错误
Fail失败匹配率 < 80%、致命错误、执行超时、人工确认失败
Review待确认嵌入行信息/sr/hs 用例需人工核对；或仅 exit_code 异常但无其他失败
NT未测试尚未执行

判定优先级

  1. 帧同步检测（--showmetadata 用例）— 最高优先
  2. 嵌入行信息 / SR/HS — 自动标记 Review
  3. 帧率精确匹配 — FPS Pass 后 exit_code 非零降级为 warning
  4. 帧率稳定性 — 所有 sensor > 20fps
  5. 关键字 + 文件 + 数量 — 80% 匹配阈值
  6. 严重错误检测 — exception/crash/timeout/abort 等

日志查看

执行过程中底部日志面板实时显示：

  • 蓝色/白色 — 正常信息（命令执行、匹配结果）
  • 黄色 — 警告（exit_code 非零但不影响判定、人工操作跳过）
  • 红色 — 错误（执行异常、SSH 断连、超时）

点击「单独查看」或「日志大屏」可进入全屏日志页面，支持清空日志。日志在页面刷新后清空。

日志中以 [DEBUG] 开头的行显示解析后的步骤列表，可用于排查用例解析是否正确。

测试用例创建（A1→A5 向导）

侧边导航「用例创建」提供从项目信息收集到可执行用例导出的完整链路，替代手工编写 Excel。

A1-A5 问答 → 硬件拓扑表 → 覆盖矩阵 → 生成用例 → 编辑校验 → 导出 xlsx
A步骤 1 · A1→A5 分批问答

按以下顺序分批填写项目信息，每一批先补齐关键信息再进入下一批：

批次收集内容关键字段
A1文档元信息（封面/修改控制）title / file_number / doc_version / references
A2被测对象维度（覆盖度根信息）stream_program / cam_config / fps_by_module / debug_dir / board_ip / command_args / feature_criteria
A2 跳板机跳板机 / 传输 / 执行模式jump_host_enabled / execution_mode / scp_source_path / stream_success_signal / functional_timeout
A2 故障特殊测试 / 故障变体special_tests / fault_expand_mode / fault_report_mode / fault_syslog
A3公共前置条件driver_deploy_dir / test_tool_path / exception_handling
A4分类与优先级规则test_type_scope / method_rule / priority_rule / id_rule
A5输出要求 / 选填增强generation_scope / output_format / screenshot_column / optional_notes
命令、路径、IP、阈值、帧率等项目特定信息不会自动编造。缺失时生成用例保留 <待补充:xxx> 占位符，导出后按占位符清单补齐。
B步骤 2 · 硬件拓扑 → 覆盖矩阵

填写硬件拓扑表（Group / Link / 模组型号 / 解串器 / I2C地址 / sensor-id / mask位），覆盖矩阵的模组行由拓扑自动生成，勾选要测的功能即可。

拓扑表示例： Group 模组型号 Link mask位 GroupA IMX728 LinkA 0x1 GroupA IMX623 LinkB 0x10 GroupB OX03F10 LinkA 0x1 → 自动生成 -m mask： IMX728 → -m "0x1 0 0 0" IMX623 → -m "0x10 0 0 0" OX03F10 → -m "0 0x1 0 0"
匹配字段是模组型号。sensor 地址是 I2C 地址，不参与矩阵/拓扑匹配。优先级：用户填写 mask位 > sensor-id % 4 > Link A/B/C/D 默认位。
C步骤 3 · 按矩阵生成用例

点击「按矩阵生成用例」按钮，规则模板按 A2-A5 配置生成用例骨架：

  • 起流命令：用 A2 的程序名 + 配置名 + 拓扑 mask，缺失留 <待补充:-c配置名>
  • 前置条件：用 A3 驱动目录 + 板端 IP + 调试目录拼装
  • 预期结果：含帧率 30fps / 产物 .raw / 无报错 等可判定观测点
  • 逐模组帧率：按 fps_by_module 精确匹配，未匹配留 <待补充:帧率>

可选「启用 AI 增强」（无拓扑时），AI 不可用时自动降级规则版。有拓扑时为保证 mask 精确，AI 生成被禁用。

D用例编辑与规范校验

生成后进入步骤 3 编辑用例，列表新增「规范」列实时校验：

  • ✅ 可判定 预期结果含可观测点（产物后缀 / 帧率 / 无报错 / 关键字）
  • ⚠️ 需补充 预期结果缺少可判定关键字，引擎将只能依赖退出码判定（置信度低）

点击「插入示例」可填入真实黄金用例（起流+出图），改模组名即可用。

E步骤 5 · 导出

导出生成两份 xlsx：

  • 测试用例_内部版.xlsx — 含全部字段与占位符标注
  • 测试用例_客户版.xlsx — 脱敏版，用于交付

导出页面列出占位符清单与默认值清单。请按清单补齐 <待补充:xxx> 后再上传执行。

导出的 xlsx 可直接上传到执行侧。经实测，用例经 ExcelHandler.load() 解析后 expected_keywords 非空（如 30fps / streaming started / .raw），可被引擎正常判定。
