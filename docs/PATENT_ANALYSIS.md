## 1. 系统概述

本系统是一个 **Excel 测试用例驱动的 Web 测试执行平台**，核心功能包括：

1. **智能 Excel 解析**：自适应识别多种表格布局（有表头/无表头/混合），自动映射列语义
2. **自然语言命令提取**：从自由文本测试步骤中智能提取可执行命令（支持 7 种命令模式）
3. **自然语言预期结果解析**：从非结构化文本中自动提取判定标准（关键字、数值范围、文件存在性等）
4. **多模式 SSH 执行引擎**：支持直连/跳板机、交互式 PTY、并行工具命令协调执行
5. **智能结果判定引擎**：基于多规则融合（关键字匹配率、帧率动态容忍、十六进制数据比对）自动判定 Pass/Fail
6. **半自动化人工确认机制**：WebSocket 双向通信实现执行中的人机协同交互
7. **结构化日志与可视化报告**：每用例独立日志 + 语义高亮 + HTML 报告

## 2. 技术创新点详细分析

### 2.1 创新点一：自适应 Excel 测试用例布局识别与列语义映射

**技术描述：**

系统实现了一套三级递进的 Excel 列语义识别机制：

```
第 1 层：表头关键词扫描
  → 在多行范围内扫描单元格，计算命中关键词的字段数
  → 选择最优表头行（命中字段数最多者）
  → 基于表头关键词映射列号

第 2 层：内容特征推断（无表头时）
  → 基于预定义的内容特征库（如 'sudo'→test_steps, '硬件连接'→prerequisites）
  → 对数据区域进行统计打分
  → 选择得分最高的列作为对应语义列

第 3 层：默认列号兜底
  → 当以上两层均未匹配时，使用预设的默认列映射
```

**代码实现位置：**
- `excel_handler.py::_find_header_and_data_rows()` — 表头行定位
- `excel_handler.py::_detect_column_map()` — 关键词映射
- `excel_handler.py::_infer_columns_by_content()` — 内容特征推断

**可专利性评估：**

| 维度 | 评估 |
|---|---|
| 新颖性 | ⭐⭐⭐⭐ 高。现有工具（如 TestLink、Zephyr）要求固定模板，动态布局识别在测试用例领域较少见 |
| 创造性 | ⭐⭐⭐ 中高。多级递进策略（表头→内容→默认）具有一定的组合创新性 |
| 实用性 | ⭐⭐⭐⭐⭐ 极高。直接解决了测试团队表格格式不一致的痛点 |

**专利方向建议：**

### 2.2 创新点二：自然语言测试步骤到可执行命令的智能提取

**技术描述：**

系统实现了从自由文本测试步骤中提取可执行命令的能力，核心是一个**优先级命令匹配引擎**：

```python
COMMAND_PATTERNS = [
    # 优先级 0：显式标记
    (r'执行(命令|指令)[：:]\s*(.+)', 'explicit'),
    (r'输入(命令|指令)[：:]\s*(.+)', 'explicit'),
    # 优先级 1：交互式工具
    (r'\./nvsipl_camera\s+', 'interactive'),
    # 优先级 2：直接路径
    (r'(?:\./|\w+/)[a-zA-Z_]+\s*[\w\s"\-]*', 'direct_path'),
    # 优先级 3：特殊工具
    (r'i2cmastercmd\s+.*', 'special_tool'),
    # 优先级 4：sudo 命令
    (r'sudo\s+\S+', 'sudo'),
    # 优先级 5：反引号命令
    (r'`([^`]+)`', 'backtick'),
    # 优先级 6：目录切换
    (r'cd\s+\S+', 'cd'),
]
```

同时实现了**智能合并策略**：
- **交互输入合并**：将 `nvsipl_camera` + 后续交互输入（如 `dl 8`）合并为 `printf '%s\n' 'dl 8' | ./nvsipl_camera`
- **并行工具协调**：将 `nvsipl_camera` + `i2cmastercmd` 识别为并行执行场景，自动编排后台启动→等待初始化→前台执行→kill 读取的流程

**代码实现位置：**
- `command_parser.py` — 完整 430+ 行命令解析引擎

**可专利性评估：**

| 维度 | 评估 |
|---|---|
| 新颖性 | ⭐⭐⭐⭐⭐ 极高。将 NLP 思想应用于测试步骤命令提取，在测试执行领域具有开创性 |
| 创造性 | ⭐⭐⭐⭐ 高。优先级模式匹配 + 上下文感知的命令合并策略具有显著创造性 |
| 实用性 | ⭐⭐⭐⭐⭐ 极高。使自然语言编写的测试用例可直接被机器执行 |

**专利方向建议：**

### 2.3 创新点三：自然语言预期结果到自动化判定标准的智能解析

**技术描述：**

系统实现了从非结构化预期结果文本中提取结构化判定标准的能力，核心是一个**多维度判定标准提取引擎**：

```
输入（自然语言）：
  "正常起流，帧率稳定在30fps，无报错信息，可生成.raw文件"

输出（结构化判定标准）：
  {
    keywords: ["30fps", "raw文件"],
    framerate: {target: 30, tolerance: 0.2, min: 24, max: 36},
    file_checks: [{pattern: "*.raw", op: "exists"}],
    exit_code: 0,
    comparison: None
  }
```

提取规则覆盖 6 大类：
1. **帧率检测**：`(\d+)\s*fps` → 目标帧率 ±20% 容忍
2. **文件存在性**：`生成.*\.raw` → 文件存在检查
3. **关键字匹配**：显式引号内容或中文描述
4. **十六进制比对**：`一致`、`匹配` → 数据比对模式
5. **退出码检查**：`无报错`、`返回码为0`
6. **NA 自动识别**：`待写入`、`TBD`、`N/A` 等

**代码实现位置：**
- `expected_parser.py` — 完整 650+ 行预期结果解析引擎

**可专利性评估：**

| 维度 | 评估 |
|---|---|
| 新颖性 | ⭐⭐⭐⭐⭐ 极高。将自然语言预期结果自动转换为可执行的判定标准，在软件测试领域属首创 |
| 创造性 | ⭐⭐⭐⭐ 高。多维度提取规则的组合以及容错机制（如帧率±20%动态容忍）具有创造性 |
| 实用性 | ⭐⭐⭐⭐⭐ 极高。消除了人工编写判定脚本的需求 |

**专利方向建议：**

> **"一种基于自然语言的测试预期结果自动解析与判定标准生成方法"**
>
> 核心权利要求可覆盖：
> 1. 基于正则模式的预期结果语义分类方法
> 2. 帧率类指标的动态容忍范围计算方法
> 3. 文件存在性检查的自动推导方法
> 4. 多判定标准融合的综合判定方法
> 5. 不适用（NA）测试用例的自动识别方法

### 2.4 创新点四：多模式 SSH 远程测试执行引擎

**技术描述：**

系统实现了支持多种网络拓扑和设备交互模式的 SSH 远程测试执行引擎：

```
直连模式：
  PC ──────→ 目标设备

跳板机模式（双跳隧道）：
  PC ──paramiko──→ 跳板机 ──direct-tcpip隧道──→ 目标设备

交互式执行模式：
  打开 PTY → 发送命令 → 循环读取输出 → 检测提示符 → 返回结果

并行工具协调模式：
  后台启动工具A → 等待初始化标志 → 前台执行工具B → Kill工具A → 合并输出
```

关键技术点：
- **跳板机隧道**：通过 Paramiko 的 `set_keepalive` + 本地端口转发实现双跳连接
- **交互式 PTY**：分配伪终端，支持需要交互输入的命令（如 `nvsipl_camera`）
- **并行工具协调**：后台进程管理 + 初始化标志检测 + 输出合并

**代码实现位置：**
- `ssh_manager.py` — SSH 连接管理
- `executor_adapter.py::execute_nvsipl_with_parallel_tool()` — 并行工具协调
- `executor_adapter.py::execute_step()` — 交互式执行

| 创造性 | ⭐⭐⭐ 中高。跳板机隧道 + 交互式 PTY + 并行工具协调的组合方案具有创造性 |

### 2.5 创新点五：基于多规则融合的智能测试结果判定引擎

**技术描述：**

系统实现了基于多规则融合的自动化测试结果判定：

```
判定流程：
  1. NA 检测 → 如果是 NA，直接返回 NA
  2. 前置条件失败检测 → 如果有 BLOCK 标记，返回 BLOCK
  3. 多步骤结果聚合：
     - 如果有任一步骤 FAIL → 整体 FAIL
     - 如果所有步骤 PASS → 整体 PASS
  4. 单步判定（基于预期结果类型）：
     a. 关键字匹配：匹配率 ≥ 80% → PASS
     b. 帧率检查：实际帧率在 [target*(1-tol), target*(1+tol)] → PASS
     c. 文件存在性：glob 匹配到文件 → PASS
     d. 十六进制比对：一致率 ≥ 80% → PASS
     e. 退出码检查：exit_code == 0 → PASS
  5. 严重错误覆盖：输出中包含严重错误关键字 → 强制 FAIL
```

**代码实现位置：**
- `executor_adapter.py::_determine_overall_status()` — 多步骤聚合
- `executor_adapter.py::_check_severe_errors()` — 严重错误覆盖
- `expected_parser.py` — 各类判定标准提取

**可专利性评估：**

| 维度 | 评估 |
|---|---|
| 新颖性 | ⭐⭐⭐ 中。多规则判定本身不新颖，但在嵌入式相机测试场景的具体规则设计有新意 |
| 创造性 | ⭐⭐⭐ 中。帧率动态容忍 + 十六进制比对 + 严重错误覆盖的组合具有领域创造性 |
| 实用性 | ⭐⭐⭐⭐ 高。直接替代了人工目视判断 |

**专利方向建议：**

> **"一种基于多规则融合的嵌入式设备测试结果自动判定方法"**

### 2.6 创新点六：基于 WebSocket 的半自动化人机协同测试执行机制

**技术描述：**

系统实现了测试执行过程中的人机协同交互机制：

```
执行流程中遇到需要人工判断的步骤：
  1. 后端识别 MANUAL_CONFIRM 标记
  2. 通过 WebSocket 广播 manual_confirm_request 事件
  3. 前端展示确认界面（通过/不通过/跳过）
  4. 用户使用辅助工具（如相机预览、图像查看）进行判断
  5. 用户点击确认按钮
  6. 前端通过 WebSocket 发送 confirm_response
  7. 后端收到响应，唤醒等待事件，继续执行
  8. 根据用户判断结果记录 Pass/Fail
```

技术特点：
- **异步事件驱动**：使用 `asyncio.Event` 实现执行线程的等待/唤醒
- **双向实时通信**：WebSocket 同时承载请求和响应
- **执行状态保持**：人工确认期间执行上下文完整保留

**代码实现位置：**
- `websocket/manager.py::request_manual_confirm()` — 确认请求
- `executor_adapter.py` 中的 MANUAL_CONFIRM 处理逻辑

**可专利性评估：**

| 维度 | 评估 |
|---|---|
| 新颖性 | ⭐⭐⭐⭐ 高。在自动化测试执行中嵌入人工判断节点，并通过 WebSocket 实时交互的方案较新颖 |
| 创造性 | ⭐⭐⭐ 中高。异步事件驱动的半自动化执行流程具有创造性 |
| 实用性 | ⭐⭐⭐⭐ 高。解决了"不能完全自动化"的测试场景 |

**专利方向建议：**

> **"一种基于实时双向通信的半自动化测试执行与人机协同判定方法"**
